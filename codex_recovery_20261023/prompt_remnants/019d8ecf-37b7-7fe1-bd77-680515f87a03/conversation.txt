The Insights tab in our iOS app cannot scroll. The Home and Block List tabs scroll fine. The Insights tab embeds a DeviceActivityReport view (an Apple system-hosted remote view from the DeviceActivity framework) inside a ScrollView.

The problem: DeviceActivityReport is a remote-hosted view (ExtensionKit/UIViewRepresentable). It doesn't report intrinsic content size. Without a .frame, it collapses to zero height. With a fixed .frame(minHeight: 540), it renders but the entire tab becomes non-scrollable because the remote view swallows scroll gestures.

Investigate:

1. Read InsightsView.swift at ScreenTime/Sources/App/Features/Insights/InsightsView.swift — show the full current layout hierarchy

2. Read ScreenTimeReportExtension.swift at ScreenTime/Sources/Extensions/DeviceActivityReport/ScreenTimeReportExtension.swift — show the full extension view structure

3. Read HomeView.swift and BlockListView.swift to understand how those tabs implement scrolling successfully

4. Research how DeviceActivityReport (Apple's remote hosted SwiftUI view) interacts with ScrollView. Specifically:
   - Does it use UIHostingController under the hood?
   - Does it intercept scroll gestures?
   - How do other apps solve this? Look at any open source Screen Time API projects for patterns.

5. Identify ALL possible solutions:
   - Can we disable scroll gesture interception on the remote view?
   - Should we use a fixed height that matches the content and recalculate it?
   - Should the ScrollView be inside the extension instead of the parent app?
   - Should we use UIScrollView instead of SwiftUI ScrollView?
   - Does .scrollDisabled(false) or .allowsHitTesting help?
   - Does wrapping in a GeometryReader help?
   - Does using .fixedSize(horizontal: false, vertical: true) help?

6. Recommend the single best approach with exact code showing where it should be applied in InsightsView.swift and/or ScreenTimeReportExtension.swift.
