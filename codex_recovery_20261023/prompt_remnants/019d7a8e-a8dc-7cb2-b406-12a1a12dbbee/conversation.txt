BUG: iOS Shield Extension Cannot Write to UserDefaults

PROJECT: iOS screen time app at /Users/antonioperedo/Desktop/screen_time/ScreenTime.xcodeproj
LANGUAGE: Swift, SwiftUI
TARGETS: Main app + 4 extensions (ShieldConfigurationExtension, ShieldActionExtension, DeviceActivityMonitorExtension, DeviceActivityReportExtension)
APP GROUP: group.com.antonioperedo.screentime

PROBLEM:
The ShieldConfigurationExtension (a ShieldConfigurationDataSource subclass) is blocked by iOS sandbox from writing to UserDefaults via cfprefsd. Console shows:
"Sandbox: ShieldConfigurationExtension deny(1) file-write-data ...group.com.antonioperedo.screentime.plist"
"rejecting write of key(s) ... because setting preferences outside an application's container requires user-preference-write or file-write-data sandbox access"

Apple confirmed this is by design for ShieldConfigurationDataSource extensions. They CAN read UserDefaults and CAN write files to the App Group container via FileManager. They CANNOT write to UserDefaults.

The shield screen shows "Attempt #0 today" every time because the write to store the hit count fails silently.

FILES TO CHANGE:

1. ScreenTime/Sources/Extensions/ShieldConfiguration/ShieldConfigurationProvider.swift
   - This file has 4 UserDefaults write calls that all fail:
     a. Line ~65: store.resetHitCountIfNewDay() — writes todayHitCount and hitCountDate to UserDefaults
     b. Line ~74: store.appendShieldHitAndCountForDay(record) — the file write works, but after the file write it calls store.setInt(todayHitCount) and store.setString(hitCountDate) which fail
     c. Line ~146: store.setString(message, forKey: lastShieldMessageText) — fails
     d. Line ~158: store.setString(pick.template, forKey: lastShieldMessageText) — fails

2. ScreenTime/Sources/Shared/SharedDataStore.swift
   - appendShieldHitAndCountForDay method writes to JSON file (works) then writes to UserDefaults (fails)
   - Need to separate the file write from the UserDefaults cache update

3. ScreenTime/Sources/Shared/SharedConstants.swift
   - Need to add a new file constant for the last shield message

FIX:

Step 1: In SharedDataStore.swift, split appendShieldHitAndCountForDay into two parts:
   - appendShieldHitAndReturnCount(_:) — writes to shield_hits.json via NSFileCoordinator (this WORKS), counts today's records from the file, returns the count. Does NOT touch UserDefaults at all.
   - updateHitCountCache(count:date:) — writes todayHitCount and hitCountDate to UserDefaults. Only called by the main app, never by extensions.

Step 2: In ShieldConfigurationProvider.buildShieldConfiguration:
   - Remove the call to store.resetHitCountIfNewDay(). Not needed because the count comes from filtering the JSON file by calendar day, which naturally handles day boundaries.
   - Replace store.appendShieldHitAndCountForDay(record) with the new store.appendShieldHitAndReturnCount(record). This writes the file and returns the correct count without touching UserDefaults.

Step 3: Replace lastShieldMessageText UserDefaults storage with a file:
   - Add to SharedConstants.Files: static let lastShieldMessage = "last_shield_message.txt"
   - In ShieldConfigurationProvider.resolveMessage, read the last message from this file: store.readRawData(fileName: SharedConstants.Files.lastShieldMessage) decoded as UTF8 string
   - After picking a new message, write it to this file: store.writeRawData(message.data(using: .utf8), fileName: SharedConstants.Files.lastShieldMessage)
   - This replaces the two store.setString calls for lastShieldMessageText

Step 4: In the main app, make sure the UserDefaults cache still gets updated for UI purposes:
   - In BlockingManager.restoreMonitoringIfNeeded() or wherever the main app refreshes on foreground, call the new updateHitCountCache method by reading the count from shield_hits.json and writing it to UserDefaults. The main app CAN write to UserDefaults.
   - Also update MainTabView's computeLiveSnapshot to read todayHitCount from the JSON file via countShieldHitsToday() instead of from the UserDefaults cache.

Step 5: In TestScreenView.swift, if it reads todayHitCount from UserDefaults directly, change it to use store.countShieldHitsToday() which reads from the JSON file.

VERIFICATION:
- The ShieldConfigurationProvider must have ZERO calls to store.setInt, store.setString, store.setBool, or store.resetHitCountIfNewDay. Search the file and confirm no UserDefaults writes remain.
- Build both schemes: "ScreenTime" (device) and "ScreenTime-UIOnly" (simulator). Zero errors.
- The shield screen should now show incrementing attempt counts because the count comes from the JSON file which the extension CAN write to.

Do NOT change any other files or features. Only fix the shield extension write issue.
